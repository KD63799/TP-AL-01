# TP S4 · ADR-004 : pourquoi isoler cette dépendance derrière un port ?

**Durée** : 45 min · **Travail** : individuel · **Livrable** : `docs/adr/ADR-004-port.md` (format allégé, avec l'hexagone) + un petit diff (environ 20 lignes, test vert)

## Objectif

Le test S4 de votre variante désigne un use case qui dépend directement d'une classe d'`infra/`. Répondre à la question : **pourquoi isoler cette dépendance derrière un port, et sous quel nom métier ?** Puis faire le geste, et faire passer le test.

| Variante | Test | Use case concerné |
|----------|------|-------------------|
| Billetterie | `test/s4/billetterie.spec.ts` | `ConsulterCapaciteUseCase` |
| Matériel hospitalier | `test/s4/hopital.spec.ts` | `HistoriqueRessourceUseCase` |
| Coworking multi-sites | `test/s4/coworking.spec.ts` | `ListerRessourcesUseCase` |
| Autopartage | `test/s4/autopartage.spec.ts` | `RechercherRessourcesProchesUseCase` |
| Salles municipales | `test/s4/salles.spec.ts` | `PayerUseCase` |
| Équipements sportifs | `test/s4/sports.spec.ts` | `RembourserUseCase` |

**Déjà fournis** : l'adapter in-memory (`infra/in-memory-*.ts`), le token d'injection (`ports/tokens.ts`) et le test. **À écrire par vous** : l'interface du port.

## Consignes

### 1. ADR-004 (format allégé)

- **Contexte** : le use case, la classe d'`infra/` dont il dépend, et l'attribut qualité d'ADR-001 que cette dépendance menace.
- **Alternative écartée** : une seule (par exemple : garder la dépendance directe, ou remplacer la classe par un mock dans les tests).
- **Décision** : le nom du port, **dans le langage du domaine** (pas le nom de la technologie). Il peut différer du nom du token.
- **Figure** : dans l'hexagone déjà présent, remplacez les trois `???` (port, adapter in-memory, adapter réel).

### 2. Le port

Créez `src/<module>/ports/<nom>.port.ts` :
- une interface, avec **uniquement** les méthodes que le use case appelle ;
- des signatures identiques à celles de l'adapter in-memory fourni (même nom de méthode, mêmes paramètres, même type de retour) ;
- n'importez que des types du module (`../ressource.js`, `../domain/...`, `../entree-journal.js`, `../paiement.js`), jamais `infra/` : la règle `ports-sans-infra` le vérifie.

### 3. Le use case

- Remplacez le paramètre du constructeur typé par la classe d'`infra/` par `@Inject(<TOKEN>) private readonly ...: <VotrePort>`.
- Importez l'interface avec **`import type`**, sinon `npm run build` échoue (erreur TS1272).
- Le use case ne doit plus importer la classe d'`infra/`.

### 4. Le module

Dans `<module>.module.ts`, reliez le token à l'adapter réel. D'abord, cherchez `<ClasseInfra>` dans tout `src/` (recherche globale de l'éditeur) :
- la classe n'est injectée par **aucun autre** use case : remplacez-la dans les providers par `{ provide: <TOKEN>, useClass: <ClasseInfra> }` ;
- la classe est **encore injectée ailleurs** : gardez-la dans les providers et ajoutez `{ provide: <TOKEN>, useExisting: <ClasseInfra> }`.

`npm run test:demarrage` vérifie que toute l'application se câble : c'est lui qui détecte un binding oublié ou erroné.

Le geste montré en démonstration sur `EnvoyerNotificationUseCase` est le même.

## Critères de réussite

- [ ] `npm run test:s4 -- <variante>` et `npm run test:demarrage` passent
- [ ] `npm run build` passe (types vérifiés) et `npm run depcruise` ne signale aucune violation
- [ ] le port porte un nom métier et n'expose que les méthodes utiles
- [ ] ADR-004 : contexte en 2 phrases, une alternative, une conséquence, l'hexagone complété
- [ ] statut « Accepté », date et variante renseignées

## En cas d'erreur

| Message | Cause probable |
|---------|----------------|
| `Nest can't resolve dependencies of the X (?) ... argument <Classe>` (test S4) | le use case est encore typé par la classe d'`infra/` |
| `Nest can't resolve dependencies of the X (?) ... argument Symbol(...)` (test de démarrage) | le token n'est pas relié dans le module |
| `Nest can't resolve dependencies of the Y (?) ... argument <Classe>` (test de démarrage) | `useClass` utilisé alors que la classe est encore injectée ailleurs : passez à `useExisting` |
| `TS1272: A type referenced in a decorated signature must be imported with 'import type' or a namespace import ...` | l'interface est importée sans `import type` |
| `ports-sans-infra` dans `npm run depcruise` | le port importe un type d'`infra/` |
